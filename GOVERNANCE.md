# Governance

LynxFlow currently follows a **maintainer-led** model:

- Maintainers review pull requests and set release priorities.
- Substantial architecture changes should be recorded as ADRs under `docs/adr/`.
- Security-sensitive reports are handled according to `SECURITY.md`.

As the contributor base grows, additional maintainers may be added based on sustained, high-quality participation.

## Decision priorities

1. User privacy and data control
2. Local-first functionality
3. Clear module boundaries and maintainability
4. Contributor experience
